## 论文针对什么问题

论文观察到，当前部署中的 LLM agent（如 Claude Code、Codex CLI、Gemini CLI）已经承担了大量传统操作系统的职责：读写文件、启动进程和子代理、获取网络内容、加载第三方扩展、保存并恢复会话状态等。这些能力大约在三年内相继出现，但没有获得操作系统用五十多年建立起来的保护机制。无论模型输出什么——是否遵循用户、工具结果或下载的技能——都会以宿主用户的完整权限执行，效果上等同于运行在 ring 0。

现有防御通常只能整体沙箱化 agent 或审查其扩展，agent 内部不受保护；写在提示词里的规则也不满足 Anderson 参考监视器的三条标准：不可绕过、防篡改、可验证。作者因此提出：部署中的 agent 本身已经类似一个操作系统，应当将其作为操作系统来分析，即 AaOS（Agents as Operating Systems）。

## 提出了什么解决方案

作者提出一个系统化分析框架：把已经部署的 agent 当作操作系统，以标准 OS 教科书中的机制为清单，将 19 个子系统中的 116 个机制映射到 agent 的对应物，并对每个机制打上五种标签：

- **isomorphic**：同构，机制和 OS 对应物基本一致；
- **degraded**：功能存在，但保护依赖模型本身；
- **missing**：完全缺失；
- **mutated**：发生变异；
- **novel**：agent 场景下新出现。

在此基础上，论文用实验验证文档无法确定执行情况的机制，识别哪些 OS 防御无法直接迁移，并推导出开放问题的优先级列表。需要说明的是，该论文主要贡献是一个分析和审计框架，而不是一个新的可部署防御系统。

## 具体是怎么做的

- **机制映射**：从产品文档、源代码和相关文献中，将 19 个 OS 子系统的 116 个机制映射到 agent 对应物，并按 isomorphic / degraded / missing / mutated / novel 分类。
- **实验验证**：针对 25 个仅靠文档无法确定实际执行情况的机制，在 Claude Code、Codex CLI、Gemini CLI 上进行了 13 个实验。
- **实验结论分类**：16 个机制与分析一致；7 个获得更精确描述；2 个修正了原判断。
- **关键实验发现**：
  - 访问检查位于各个工具内部，而不是进程层面，因此文件工具拒绝的写入可以通过 shell 绕过。
  - 三个 CLI 在恢复会话时都会加载伪造的 transcript record 作为用户消息，并接受由工具返回的时间。
  - 任务控制较弱：task id 指向的是 wrapper，而不是底层进程。
  - 子代理继承父级权限。
  - 基于模型的权限监视器接收的是由 agent 自己控制的文本。
- 论文还识别出五个没有对应 OS 防御可迁移的问题，并从机制映射的缺口推导出优先开放问题列表。

## 取得了什么效果

- 在 116 个机制的映射中，只有 11 个是同构的，65 个完全缺失；缺失的大多是保护类机制，包括权限分离、资源配额、事务和防篡改审计。
- 通过实验确认了多个实际缺陷：工具内访问检查可被 shell 绕过；会话恢复信任 agent 自身记录；任务控制、子代理权限和基于模型的监视器较弱。
- 论文识别出五个 OS 防御无法迁移的问题，并给出了开放问题优先级列表，为后续研究提供议程。
- 原文摘录未提供标准化安全基准、防御性能指标或完整实验设置细节，因此论文效果主要体现在机制覆盖和定性发现上，而非量化安全提升。

## 旁观者视角的问题与不足

- **可复现性信息不足**：摘要提到 13 个实验、25 个机制、3 个 CLI，但没有提供具体版本、实验环境、操作步骤、判定标准或原始数据；读者无法独立验证“16 / 7 / 2”的判定结果。
- **映射分类可能带有主观性**：116 个机制的标签判断依赖作者对文档、源码和文献的理解，但正文摘录未给出完整分类表、标注流程或一致性检验；agent 文档和实现更新很快，静态映射容易过时。
- **威胁模型说明不足**：例如“三个 CLI 加载伪造 transcript record”这一发现很重要，但摘要/摘录没有说明攻击者需要何种前置能力（是否需本地文件写入、是否需已有会话访问等），因此难以判断实际风险等级。
- **覆盖范围有限**：仅覆盖三个主流 coding CLI，且机制清单基于“标准 OS 教科书”，可能偏向经典单机 OS 保护模型；对 agent 特有的提示注入、信息流、模型不确定性等威胁的覆盖程度在摘要中未充分说明。
- **没有防御实现**：论文识别问题和开放问题，但没有提出或评估可部署的原型；对于期望看到系统设计的读者，当前信息不足。

## 值得继续追踪的点

- 论文提出的优先级开放问题列表的具体内容，以及五个“无 OS 防御可迁移”的问题分别是什么。
- 19 个子系统 116 个机制的完整映射结果，尤其是 degraded / mutated / novel 类别的详细定义和案例。
- 三个 CLI 的会话恢复信任、工具内访问检查、子代理继承权限等问题是否会被厂商修复。
- 面向 agent 内部的参考监视器设计：如何让规则同时满足不可绕过、防篡改、可验证。
- 该 AaOS 分析框架是否会被后续工作采用或扩展，以及论文是否有后续版本或正式发表。
- arXiv 链接为 `2610.33753v1`，可关注后续版本更新。
